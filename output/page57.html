Azure Cloud HSM Hardware Audit Logging: Verifiable audit trails for security and compliance

📅 Oct 29, 2026  |  Category: Business  |  Read Source →

<p class="wp-block-paragraph">Organizations running regulated and security-sensitive workloads need trusted evidence of which authenticated users performed management operations on their hardware security modules (HSMs), what actions they took, and when. Today, we are announcing Hardware Audit Logging for <a href="https://azure.microsoft.com/en-us/products/cloud-hsm" rel="noopener noreferrer" target="_blank">Azure Cloud HSM</a>, which collects audit records generated by the HSM itself for supported management operations. Security, compliance, and operations teams can use this hardware-originated evidence for monitoring, compliance reporting, and forensic investigations.</p> <div class="wp-block-buttons is-content-justification-center is-layout-flex wp-container-core-buttons-is-layout-a89b3969 wp-block-buttons-is-layout-flex"> <div class="wp-block-button"><a class="wp-block-button__link wp-element-button" href="https://azure.microsoft.com/en-us/products/cloud-hsm" rel="noopener noreferrer" target="_blank">Learn more about Azure Cloud HSM</a></div> </div> <h2 class="wp-block-heading" id="why-hardware-generated-audit-evidence-matters">Why hardware-generated audit evidence matters</h2> <p class="wp-block-paragraph">HSMs protect some of an organization&#8217;s most sensitive cryptographic assets. The security of those assets depends not only on how keys are generated and protected, but also on how the HSM is configured and administered over time. Authentication events, user changes, policy updates, backup operations, and key lifecycle activity can all be important when teams investigate an incident, validate operational controls, or prepare evidence for an audit.</p> <p class="wp-block-paragraph">Traditional platform and application logs remain valuable, but regulated organizations often want evidence that originates as close as possible to the protected cryptographic boundary. By sourcing audit information directly from the HSM, <a href="https://learn.microsoft.com/en-us/azure/cloud-hsm/" rel="noopener noreferrer" target="_blank">Azure Cloud HSM</a> provides records tied to the device performing the protected operations. This gives customers an additional layer of evidence for understanding administrative activity and validating the records incorporated into their monitoring and compliance processes.</p> <h2 class="wp-block-heading" id="monitor-hsm-management-operations-with-hardware-generated-audit-logs">Monitor HSM management operations with hardware-generated audit logs</h2> <p class="wp-block-paragraph">Hardware Audit Logging captures a broad range of HSM management activities, including:</p> <ul class="wp-block-list"> <li class="wp-block-list-item">User authentication and session events.</li> <li class="wp-block-list-item">User and administrator management.</li> <li class="wp-block-list-item">Policy and configuration changes.</li> <li class="wp-block-list-item">Key lifecycle operations.</li> <li class="wp-block-list-item">Backup and restore activities.</li> </ul> <p class="wp-block-paragraph">Together, these events help organizations build a more complete view of how the HSM is being operated. Security teams can examine authentication and administrative activity, compliance teams can use the records as evidence for control assessments, and operations teams can investigate configuration or lifecycle changes that may affect a protected workload.</p> <h2 class="wp-block-heading" id="independent-end-to-end-audit-verification">Independent, end-to-end audit verification</h2> <p class="wp-block-paragraph">Customers can access human-readable audit records, the corresponding HSM-signed binary audit data, signatures, and HSM certificates needed to independently verify the authenticity and integrity of signed audit batches. This customer-controlled verification path helps connect the records used in monitoring and reporting back to the signed evidence produced by the HSM.</p> <p class="wp-block-paragraph">This approach is important because auditability is not only about collecting readable events. It is also about establishing confidence in where the records came from and whether the signed audit batches remain intact.</p> <h2 class="wp-block-heading" id="maintain-consistent-audit-coverage-for-supported-management-activity">Maintain consistent audit coverage for supported management activity</h2> <p class="wp-block-paragraph">Audit logging is enabled as an immutable HSM partition policy. This design helps maintain consistent coverage of supported management activity and reduces the risk that logging could be disabled as part of routine HSM administration. For organizations that separate cryptographic administration, security monitoring, and compliance responsibilities, continuous hardware-originated logging can support clearer oversight across those functions.</p> <p class="wp-block-paragraph">The capability is designed to complement an organization&#8217;s existing governance model. Customers remain responsible for configuring access to their monitoring environment, defining retention requirements, establishing alerting and review processes, and determining how audit evidence should be used within their control framework. Hardware Audit Logging provides the HSM-originated records and verification materials that those processes can use.</p> <h2 class="wp-block-heading" id="integrate-hsm-audit-data-into-security-operations">Integrate HSM audit data into security operations</h2> <p class="wp-block-paragraph">Hardware Audit Logging is designed for organizations with stringent compliance and security requirements, including financial services, payment processing, government, critical infrastructure, and other highly regulated industries. These organizations may need to demonstrate that sensitive cryptographic systems are administered through controlled processes and that important management activities can be reviewed after the fact.</p> <p class="wp-block-paragraph">Audit events are delivered to <a href="https://learn.microsoft.com/en-us/azure/azure-monitor/logs/log-analytics-overview?tabs=simple" rel="noopener noreferrer" target="_blank">Azure Monitor Log Analytics</a>, enabling customers to incorporate HSM management activity into broader monitoring, investigation, and security operations workflows, including <a href="https://www.microsoft.com/en-us/security/business/siem-and-xdr/microsoft-sentinel-siem" rel="noopener noreferrer" target="_blank">Microsoft Sentinel</a>. Centralizing these events alongside other relevant operational and security data can help teams correlate HSM activity with events elsewhere in the environment, apply queries and analytics, and support established investigation and reporting workflows.</p> <p class="wp-block-paragraph">For example, a security operations team may want to review unexpected authentication activity, an administrator change, or a policy update in the context of related Azure activity. A compliance team may need evidence that privileged management operations were logged during a defined assessment period. An incident response team may need to reconstruct the sequence of HSM management events surrounding a security investigation. Hardware-originated audit records provide an important source for each of these scenarios.</p> <h2 class="wp-block-heading" id="strengthen-hsm-auditability-with-verifiable-evidence">Strengthen HSM auditability with verifiable evidence</h2> <p class="wp-block-paragraph"><a href="https://azure.microsoft.com/en-us/products/cloud-hsm#FAQ" rel="noopener noreferrer" target="_blank">Azure Cloud HSM</a> provides more than log visibility. Readable audit records support day-to-day operations. It also provides HSM-signed binary evidence, signatures, certificates, and verification utilities behind those records, which lead to an independent way to trace each record back to the HSM that signed it.</p> <p class="wp-block-paragraph">It also allows for keeping that evidence outside the logging workflow and checking it cryptographically whenever an audit or investigation calls for it, instead of relying only on delivered text records. Teams get an audit trail they can verify for the workloads that matter most.</p> <h2 class="wp-block-heading" id="what-does-azure-cloud-hsm-hardware-audit-logging-provide">What does Azure Cloud HSM Hardware Audit Logging provide</h2> <p class="wp-block-paragraph">It provides hardware-generated records for supported HSM management operations, sends audit events to Azure Monitor Log Analytics, and gives customers signed binary audit data and verification materials for independent validation.</p> <h2 class="wp-block-heading" id="azure-cloud-hsm-hardware-audit-logging-availability">Azure Cloud HSM Hardware Audit Logging availability</h2> <p class="wp-block-paragraph">Hardware Audit Logging is rolling out across <a href="https://azure.microsoft.com/en-us/products/cloud-hsm" rel="noopener noreferrer" target="_blank">Azure Cloud HSM</a> public regions and is automatically enabled for newly provisioned Azure Cloud HSM resources where the feature is available. Customers should review current Azure Cloud HSM regional availability and product documentation for the latest availability details and configuration guidance.</p> <p class="wp-block-paragraph">Review
