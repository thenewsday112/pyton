The presigned URL is signed for a specific operation, which you can see in the query string it hands you:<br /> </p> <div class="highlight js-code-highlight"> <pre class="highlight http"><code><span class="err">...&amp;X-Amz-Expires=60&amp;X-Amz-SignedHeaders=host&amp;x-amz-checksum-mode=ENABLED&amp;x-id=GetObject </span></code></pre> </div> <p><code>x-id=GetObject</code> is part of the signed material, so switching the verb invalidates the signature. A range GET is still a GET, which is why one byte works where zero bytes does not. That is 287.7 MiB, so it is under 300MB if you mean the binary kind and over it if you mean the decimal kind. The afterPack hook already deletes the browser for the architecture that build will never run, which is the only reason it is not twice as large.</p> <h2> What I would change </h2> <p>Both fixes are small and neither is about the upload.</p> <p>The filename triangle wants one shared constant, and it cannot have one, because <code>app/</code> and <code>server/</code> are separate packages that do not import each other. The next best thing is a test in <code>server/</code> that reads <code>app/package.json</code>, expands <code>${arch}</code> and asserts the resulting set equals the values of <code>FILES</code>. It is a ten-line test that converts a comment into a failure.</p> <p>The version header wants a reader.
